# AppleHome 兼容范围

更新：2026-10-22。当前为 **0.2.0 Preview 4**，二进制对应源码提交 [`366a8ee`](https://github.com/shenmuegit/AppleHomePod-windows/commit/366a8ee1d8694c4148ae6d5e2fa8ecee63cb1f4d)。本轮实际故障恢复与先前版本的结果分别记录。

## 2026-10-25 开发版修订（尚未发布）

10 月 24 日的再次无声现场显示，20:43 引擎停止未获确认后整个后台退出，而 Windows 仍选择 HomePod。用户确认此前经历了睡眠／唤醒；现有证据尚不能证明停止请求失效的底层原因。此前发现提供器切换已正常发生，因此不能把本次退出归为同一个发现故障，也不能将之前一次恢复出声视为长期问题已经消除。

开发版由常驻监听器监督引擎：Windows 普通播放输出选择 HomePod 时启动并持续恢复，切出时释放，切回时创建新引擎。空闲、暂停、静音和累计失败次数不终止运行意图，没有新增睡眠／唤醒释放策略。原生路径不使用历史面板的有限重试循环，身份、校准、协议、音量门和设备缓冲记录仍保留。

839 项 .NET 回归通过，含选择往返、失效引擎退役、超过旧重试次数、长时间无音频及音量／静音不改变生命周期。虚拟时钟与故障注入只能验证这些控制规则；新构建的过夜空闲与真实睡眠／唤醒仍未验收，断网测试继续不执行。下方 Preview 4 记录是已发布构建的历史事实。

本轮发生在电脑开机之后。检查时后台仍存活，Windows DNS-SD 返回空设备列表且不报错，但直接 mDNS 及程序已有备用实现能找到同一只合格 HomePod。Preview 4 安装后，11:17:16 自动切换发现来源，约 0.35 秒后重新发现设备，11:17:17 开始发送正常音乐；用户随后确认连续出声。没有修改网络、代理、服务或防火墙，也没有生成音频、录制 PCM 或使用麦克风。

验收记录有 16945 个非零 PCM 包，发送与同步错误为 0，采集到发送 p95 约 **36 ms**。这些是本地传输与队列统计，不包含 HomePod 实际出声时间，不能当作端到端延迟或音画偏差。

软件检查：830 项 .NET 测试、发布后二进制英文向导 23 项无音频检查及自包含发布通过。本次新增 4 项回归覆盖从未返回结果、初次成功后记录过期、明确权限错误和非法请求；前两个在旧实现失败，修复后通过。先前的查询故障、重连、取消、迟到结果和虚拟时钟长时间等待回归继续保留。仓库未配置 GitHub Actions，以上为本地检查。静态审核仍有 1555 个未确认导入项，不能据此宣称所有系统 API 或 Windows 环境均兼容。

Preview 4 补上了静默无结果时切换发现来源的路径，不再只重开同一个无响应的 Windows 查询。切换状态仅保存在该发现提供器实例的对应接口索引中；明确的权限和非法请求错误保留原有处理。沿用约 30 秒静默维护窗口，Windows 接口失效的系统触发因素仍未知。设备资格、认证检查、采集队列和缓冲记录保持原样。发布附件保留已安装修复版的 EXE 与源码归档，没有重新编译；归档内文档是构建时快照，当前说明以随附指南和版本说明为准。

## 参数与使用边界

音频路径为绑定的 VB-CABLE 播放端点 → WASAPI 共享模式采集 → 原生 NTP/ALAC 发送。日常使用 Windows 输出和音量控件；后台不通过静音物理扬声器消除双播，不采集麦克风。

缓冲按有效设备记录、接收端合法边界与严格匹配的型号/固件档案选择。本机沿用自己的已验证 100 ms 请求记录；它不是统一默认、声学最低值或总延迟。无记录时自动选择有依据的候选，并保留实际听感确认；不会只凭连接正常就不断压低缓冲或写入可听参考。

实际过夜空闲、系统睡眠/唤醒、重新登录、名称/绑定跨重启、独占与受保护音频、跨网段、其他播放器组合、输出往返切换、播放中停用/解绑、自定义密码、PIN 或仅家庭成员访问策略仍待验证；当前向导未提供 PIN 输入。EXE 未签名，没有自动更新渠道。

安装步骤见[英文安装指南](installation.md)或[中文首次安装](first-run.md)，精确交付文件和哈希见[本版说明](releases/v0.2.0-preview.4.md)。
