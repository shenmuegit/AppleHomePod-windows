本轮使用正常音乐和 Windows 原生控件，没有播放生成音频、录制 PCM 或使用麦克风。Windows 主音量按 74% → 60% → 74% 调整并读回，最终输出未静音。验收末次会话统计约 452 秒，采集到发送 p95 约 **33 ms**，发送与同步错误为 0；本地统计不包含 HomePod 实际出声时间，不能当作端到端延迟或音画偏差。

软件检查：启动修复后的 806 项 .NET 测试、打包后 22 项无音频界面检查及自包含发布通过；未改动的 Python 部分沿用此前 125 项测试与 Ruff 结果。静态审核仍有 1555 个未确认导入项，不能据此宣称所有系统 API 或 Windows 环境均兼容。软件检查与连接状态不能替代实际听感。

Preview 2 修复了设备发现等待提前消耗采集预缓冲、随后连接触发 `capture_preroll_overflow` 的启动问题。现在在接收端信息通过资格检查后才开始预缓冲，停止路由时清除发现等待计时；未增大采集队列上限，也未修改原有设备缓冲记录。新版界面与重播、最小窗口、焦点和系统配色回退的检查使用模拟设备，无音频发送，不作为首次安装实机验收。

## 参数与使用边界

音频路径为绑定的 VB-CABLE 播放端点 → WASAPI 共享模式采集 → 原生 NTP/ALAC 发送。日常使用 Windows 输出和音量控件；后台不通过静音物理扬声器消除双播，不采集麦克风。

缓冲按有效设备记录、接收端合法边界与严格匹配的型号/固件档案选择。本机沿用自己的已验证 100 ms 请求记录；它不是统一默认、声学最低值或总延迟。无记录时自动选择有依据的候选，并保留实际听感确认；不会只凭连接正常就不断压低缓冲或写入可听参考。

重新登录、名称/绑定跨重启、独占与受保护音频、跨网段、其他播放器组合、输出往返切换、播放中停用/解绑、自定义密码、PIN 或仅家庭成员访问策略仍待验证；当前向导未提供 PIN 输入。EXE 未签名，没有自动更新渠道。

安装步骤见[英文安装指南](installation.md)或[中文首次安装](first-run.md)，精确交付文件和哈希见[本版说明](releases/v0.2.0-preview.2.md)。
