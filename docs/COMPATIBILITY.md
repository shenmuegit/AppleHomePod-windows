本轮使用正常音乐和 Windows 原生控件，没有播放生成音频、录制 PCM 或使用麦克风。用户在 `2c7973b` 恢复候选上确认正常音乐暂停至少 1 分钟后自行恢复。最终 `9cf7933` 补充了其他健康设备不能掩盖未解析查询的维护逻辑，随后再次安装并检查后台、绑定、音量保留及活动音频发送，未要求用户重复暂停。

最终观察时已有 11622 个非零 PCM 包，发送与同步错误为 0，采集到发送 p95 约 **26 ms**。这些是本地传输与队列统计，不包含 HomePod 实际出声时间，不能当作端到端延迟或音画偏差。

软件检查：826 项 .NET 测试、发布后二进制英文向导 23 项无音频检查及自包含发布通过。故障注入覆盖查询启动、浏览、解析、查询后台错误、无响应、缓存过期、多设备查询、退避重试与取消；长时间等待使用虚拟时钟。仓库未配置 GitHub Actions，以上为本地检查。静态审核仍有 1555 个未确认导入项，不能据此宣称所有系统 API 或 Windows 环境均兼容。

## 参数与使用边界

音频路径为绑定的 VB-CABLE 播放端点 → WASAPI 共享模式采集 → 原生 NTP/ALAC 发送。日常使用 Windows 输出和音量控件；后台不通过静音物理扬声器消除双播，不采集麦克风。

缓冲按有效设备记录、接收端合法边界与严格匹配的型号/固件档案选择。本机沿用自己的已验证 100 ms 请求记录；它不是统一默认、声学最低值或总延迟。无记录时自动选择有依据的候选，并保留实际听感确认；不会只凭连接正常就不断压低缓冲或写入可听参考。

实际过夜空闲、系统睡眠/唤醒、重新登录、名称/绑定跨重启、独占与受保护音频、跨网段、其他播放器组合、输出往返切换、播放中停用/解绑、自定义密码、PIN 或仅家庭成员访问策略仍待验证；当前向导未提供 PIN 输入。EXE 未签名，没有自动更新渠道。
