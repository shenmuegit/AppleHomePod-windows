# AppleHome 首次安装与连接

解压候选包后双击 `AppleHome.exe`，进入首次安装与连接向导。无需安装 .NET、Rust 或填写音频协议参数。当前候选的实机范围是 Windows 10 x64、单只 HomePod mini、27.0 固件；其他型号、系统和立体声对尚未完成实机验证。

## 首次设置

1. **先打开向导，再安装驱动。** 向导会自动保存安装前检查，打开 [VB-Audio 官方驱动页面](https://vb-audio.com/Cable/)。下载 `VBCABLE_Driver_Pack45.zip`，解压后以管理员身份运行 x64 安装程序，按厂商提示重启。驱动由厂商单独提供，不包含在 AppleHome 包内；向导不会自动重启电脑。
2. **重启后重新打开 AppleHome。** 向导会检查真实驱动、普通播放端点及重启状态；无须重复安装。已存在且不属于本应用的驱动或被改动的任务不会被接管。
3. **选择 HomePod。** 电脑与 HomePod 应接入同一个局域网。选择列表中可连接的设备，点击“连接并验证”。未发现时可重新搜索；未验证的型号或固件会明确标注。
4. **按需确认一次 Windows 输出名称。** Windows 不允许应用直接改写该名称时，向导会打开系统声音设置，并提供可以复制的名称。选择普通 `CABLE Input` 播放设备，在“属性 → 常规”中改名，然后回到向导继续。不要选择 16ch 或录音设备。已有有效名称与绑定会保留。
5. **使用正常音乐确认。** 在 Windows 声音输出中选择向导显示的 HomePod 输出名称，用常用播放器播放音乐，并通过 Windows 音量调到舒适程度。确认正常出声后，点击“能正常听到音乐，完成设置”。向导不会向 HomePod 发送参考短音；本地音量测量在隔离的虚拟端点内完成。

如正常音乐没有声音或有断续，使用同一页的“没有声音或有断续，自动调稳”。程序会在接收端未给边界、尚无匹配参考时最多调整两次，继续使用同一首普通音乐和本次测量结果，不要求输入参数。若仍无法正常播放，则返回检查连接；不会在日常后台反复切换参数试音。

完成时才保存本次测得的校准并启用当前用户的登录后台。没有确认音乐正常、点击返回或关闭向导时，不会把试听成功写入记录；已有可用后台会按所有权校验恢复。已有安装在重新连接时复用原程序，首次设置不承担自动升级。

## 日常使用

在 Windows 输出列表选择 HomePod，直接播放音乐或视频。主音量、静音和应用混音器都使用 Windows 原生控件。后台随当前用户登录启动，日常没有独立控制面板或托盘操作。再次打开应用会显示当前设置状态。

连接参数由程序根据这台设备的有效记录、严格匹配的型号与固件参考、当前回包选择，不要求用户填写缓冲时间。没有设备记录时先自动选择有来源的候选，再实际请求；接收端有合法边界时始终遵守边界。

确认正常音乐后，只有当前会话已有实际应用值、非零音乐数据及有效观察记录，才保存这台设备的参考与资料指纹。固件、分组或播放路径改变后重新匹配；现有有效记录不会被猜测值覆盖。若提示继续播放片刻，保留音乐即可，设置进度会保留。连接曾经出错但已恢复时，会在相同参数上等待后续干净观察窗口，无须为清空历史错误提高缓冲。

这些记录表示在确认时可听，不代表已经自动测得最低声学延迟。不会仅凭连接正常就继续降低缓冲。

## 遇到问题

- **驱动已安装但无法继续：** 按向导显示的具体原因处理；歧义输出、缺失原始安装检查或外部程序占用不靠反复重启解决。不要卸载其他程序正在使用的音频驱动。
- **HomePod 没有出现或连接失败：** 确认通电、同网及 HomePod 的 AirPlay 访问设置。当前向导对要求额外 PIN 的设备会报认证错误，尚未提供 PIN 输入流程。
- **没有声音或有断续：** 在 Windows 确认选择了向导显示的输出，播放器正在播放，主音量与应用音量未静音。使用向导的自动调稳；达到有界尝试次数后重新检查连接，不要手动修改缓冲数字。

当前已完成的实机项目和未验证项目以 [验收记录](validation/windows-native-homepod-output.md) 为准。断网测试暂缓；不会使用麦克风或录制用户音乐。
