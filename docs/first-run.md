# AppleHome 首次安装与连接

解压候选包后双击 `AppleHome.exe`，进入首次安装与连接向导。无需安装 .NET、Rust 或填写音频协议参数。当前候选的实机范围是 Windows 10 x64、单只 HomePod mini、27.0 固件；其他型号、系统和立体声对尚未完成实机验证。

## 首次设置

1. **打开 AppleHome。** 安装程序保存安装前检查，核对内附的原厂 VB-CABLE Pack45，并自动安装缺少的驱动。若 Windows 询问管理员安装许可，需要用户允许；驱动要求重启时，保存工作、重启后再打开 AppleHome，程序自动继续。
2. **等待自动连接。** 电脑和 HomePod 在同一局域网时，程序完成一轮发现。只有一只符合资格的 HomePod 时自动使用；有多只时选择目标。程序自动命名普通播放端点、测量音量、选择 Windows 输出并协商连接参数。已有有效自定义名称会保留。
3. **确认是否听到。** 页面显示正在验证后，程序自动播放一次 1.5 秒提示音。回答“听到了”即保存设置、启用当前用户登录后台并关闭向导；回答“没听到”则自动检查并有限重试。无需打开声音属性、手动切换或改名、打开播放器、填写缓冲毫秒数。

未确认出声时不会保存可听参考。接收端未给边界且尚无匹配参考时，最多调整两次；重试耗尽后说明连接问题，不会把用户转到手工改名流程。日常后台不会通过反复播放提示音寻找参数。

确认后才保存本次测得的校准并启用当前用户的登录后台。取消或失败时恢复仍属于本次设置的名称、默认播放输出和音量改动，用户另外修改的值会保留。持久恢复记录在下次启动时处理异常中断。已有可用后台会按所有权校验恢复；重新连接复用原程序，首次设置不承担自动升级。

提示音只用于首次安装的明确确认步骤，不录制麦克风或用户音乐。VB-CABLE 由 VB-Audio Software 提供，采用 Donationware 模式；向导保留来源、许可和捐助入口，原始 ZIP 及全部厂商文件保持未修改。公开分发前应核对[当前分发条款](https://vb-audio.com/Services/licensing.htm)与原包 readme 的适用条件。

## 日常使用

在 Windows 输出列表选择 HomePod，直接播放音乐或视频。主音量、静音和应用混音器都使用 Windows 原生控件。后台随当前用户登录启动，日常没有独立控制面板或托盘操作。再次打开应用会显示当前设置状态。

连接参数由程序根据这台设备的有效记录、严格匹配的型号与固件参考、当前回包选择，不要求用户填写缓冲时间。没有设备记录时先自动选择有来源的候选，再实际请求；接收端有合法边界时始终遵守边界。

确认听到自动验证音频后，只有当前会话已有实际应用值、非零音频及有效观察记录，才保存这台设备的参考与资料指纹。固件、分组或播放路径改变后重新匹配；现有有效记录不会被猜测值覆盖。已有普通音乐验证的参考仍然有效。

这些记录表示在确认时可听，不代表已经自动测得最低声学延迟。不会仅凭连接正常就继续降低缓冲。

## 遇到问题

- **驱动已安装但无法继续：** 按向导显示的具体原因处理；歧义输出、缺失原始安装检查或外部程序占用不靠反复重启解决。不要卸载其他程序正在使用的音频驱动。
- **HomePod 没有出现或连接失败：** 确认通电、同网及 HomePod 的 AirPlay 访问设置。当前向导对要求额外 PIN 的设备会报认证错误，尚未提供 PIN 输入流程。
- **确认音频没有声音：** 点击“没听到”，由程序检查和重试。确认 HomePod 已通电且没有被其他设备占用；达到尝试次数后按具体错误重新检查。无需手动选择 CABLE、改名或填写数字。

自动安装候选位于 `dist/automatic-setup-20261019/AppleHome.exe`，与保留的 `AppleHome-61992a2-current-mini-20261019.zip` 分开。旧包已验证当前 mini 的正常音乐30分钟、原生音量/静音恢复、约5分钟视频主观同步及本机手动向导重装；用户否决了其安装交互。新候选的整套自动驱动安装及重启仍需独立实机验证，不能沿用旧流程的通过结论。已完成和未验证项目以[验收记录](validation/windows-native-homepod-output.md)为准，断网测试暂缓。
