# AppleHome 0.2.0 Preview 5

HomePod firmware updates no longer fail playback because of a model or firmware allowlist.

Verified repair scope: Windows 10 Pro 22H2 (build 19045, x64), one standalone HomePod mini reporting software 27.2, normal music, Windows volume changes and recovery after at least 15 seconds of mute.

## What changed

The app previously treated a timing/codec preference for one model and firmware as permission to play. An otherwise discoverable, previously working mini reporting 27.2 was rejected before the protocol handshake. [PR #2](https://github.com/shenmuegit/AppleHomePod-windows/pull/2) removes that admission check from background playback, first connection, reference preparation and the device picker, resolving [issue #1](https://github.com/shenmuegit/AppleHomePod-windows/issues/1).

- Valid discovery identity and connection details permit a connection attempt. The actual transport handshake, codec support and authentication still determine success.
- Timing and codec preferences guide the engine without blocking other models or firmware. Buffer records remain scoped to their device profile; an older firmware's reference is not treated as verified for new firmware. Buffer selection stays automatic.
- Also included since Preview 4: persistent engine supervision driven by Windows output selection. While HomePod is selected, engine failures keep recovering without a retry-count limit. Silence, pause and mute do not cancel that intent; switching away releases the engine.
- Automatic mDNS failover and setup language selection remain available. Everyday output, volume and mute are controlled through Windows.

## Installation

1. Download `AppleHome-0.2.0-6fc6482b1521.zip`, extract it and open `AppleHome.exe`.
2. Follow the wizard to install the audio driver if needed, connect HomePod and confirm audio. Save your work and restart Windows if the driver requires it.
3. Play music or video in your usual Windows apps and use Windows output, volume and mute controls.

**Existing users:** reopening the wizard reuses the installed app. Follow `INSTALL.md` or `INSTALL.zh-CN.md` to replace an older background while retaining valid device binding and calibration. There is no automatic updater. A full fresh-driver installation and restart have not been repeated for this build.

## Validation

- **846 .NET Release regression tests** passed locally, including connection without a known model/firmware profile and protection of timing-reference scope.
- **25 published-app English UI checks** passed with simulated devices, including selecting a device without a known timing profile from a list of two devices.
- Independent **Standards** and **Spec** reviews completed with no remaining findings.
- The listener accepted the repair candidate with continuous normal music, Windows volume changes and recovery after at least 15 seconds of mute. The packaged main commit has identical product and test source to that candidate; its final executable was installed and its startup, discovery, capture and streaming state checked.
- Observed send, synchronization and feedback errors were zero. The mini did not report buffer boundaries; this session used a negotiated 250 ms candidate. That value is not a universal default or measured acoustic latency.
- The final binary passed self-check and static compatibility checks. The static audit still lists 1555 unconfirmed imports and does not validate untested Windows environments. The repository has no configured GitHub Actions workflow; the test results above are local checks.

## Compatibility and remaining checks

Removing the allowlist allows devices to attempt playback; it does not establish universal compatibility. The hardware acceptance above covers one standalone mini on software 27.2 and Windows 10 build 19045 x64. Other Windows 10 builds, Windows 11, other HomePod models/firmware, stereo pairs and Apple TV groups remain unvalidated. Discovery identity, topology and protocol requirements still apply.

**Overnight idle followed by playback and real sleep/wake recovery have not been tested on hardware for this release.** An earlier supervision candidate recovered after an engine exit and output reselection, but its first reselection was delayed; seamless switching is not guaranteed. The 30-minute music and five-minute video observations in the compatibility record belong to earlier builds. Network-outage recovery and other Home access/PIN policies also need hardware validation. The executable is unsigned.

See the [compatibility record](https://github.com/shenmuegit/AppleHomePod-windows/blob/main/docs/COMPATIBILITY.md) for the evidence attributed to each build.
