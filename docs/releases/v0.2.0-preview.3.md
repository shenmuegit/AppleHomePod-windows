# AppleHome 0.2.0 Preview 3

Automatic recovery for HomePod discovery and transient audio failures, with setup that follows the Windows display language.

**Overnight idle followed by playback has not been tested on hardware.** This remains a prerelease, with hardware checks limited to Windows 10 Pro 22H2 (build 19045, x64) and one standalone HomePod mini running software 27.0.

## What changed

- Removed a two-second discovery cutoff that could terminate the background app when HomePod information was temporarily missing, leaving later playback silent.
- Failed discovery queries restart with backoff. Unresolved queries and expired records are refreshed, including when another device is healthy. Late results from cancelled queries are ignored.
- Transient audio failures can recover after a retry batch is exhausted. The background remains available to reconnect; authentication failures and unqualified device identities or profiles remain blocked.
- Setup now follows Windows preferred display languages: English, Simplified Chinese and Traditional Chinese, with English fallback. No language selector or technical connection inputs are required.

Existing device calibration, timing records, capture-queue limits, setup layout and Windows volume controls are preserved. While HomePod is in use, the 250 ms controller check reads in-memory state; it does not issue discovery requests or reconnect on each tick. Recovery uses backoff up to 30 seconds between attempts, followed by the connection handshake. This is not a guaranteed time to audible playback.

## Installation

1. Download `AppleHome-0.2.0-9cf79335d419.zip`, extract it and open `AppleHome.exe`.
2. Follow the wizard to install the audio driver if needed, connect HomePod and confirm that you hear audio. Save your work and restart Windows if the driver requires it.
3. Use your normal Windows players and the Windows output, volume and mute controls.

**Existing users:** reopening the wizard reuses the installed app. Follow `INSTALL.md` or `INSTALL.zh-CN.md` to stop the earlier background and install this repair while retaining a qualified device record. There is no automatic updater. A full fresh-driver installation and restart have not been rerun for this release.

## Validation

- **826 .NET regression tests** passed locally, including simulated discovery failures, silent/expired queries, retry exhaustion, backoff, cancellation and permanent-failure checks. Long-idle metadata tests use a virtual clock.
- **23 published-app English UI checks** passed with a simulated device and no audio. The layout is unchanged; the README images illustrate the localized setup interface.
- During this repair, a listener confirmed that normal music resumed automatically after a pause of at least one minute and remained continuous. This pause was performed on the recovery candidate before the final multi-query timeout addition; it was not independently timed or repeated afterward.
- The final binary was installed and checked for an owned, ready background task, preserved device binding and calibration, unchanged Windows output/volume, and ongoing nonzero music transport. At the recorded observation, send and synchronization errors were zero. Internal capture-to-send p95 was about 26 ms; this is **not** measured acoustic latency.

Faults were injected through automated DNS/audio test doubles. The physical network and system discovery service were not deliberately interrupted. No generated audio, short tones, PCM recording or microphone capture were used for the hardware checks. Manual volume/mute cycles, 30-minute playback and sustained video synchronization were not repeated for this binary. Earlier results on the same device remain documented separately.

These are local checks; the repository has no configured GitHub Actions workflow. A static compatibility audit still has 1555 unconfirmed imports and does not qualify untested Windows environments.

## Compatibility and remaining checks

The native wizard enables the single HomePod mini `AudioAccessory5,1 / 27.0` profile. Other Windows 10 builds, Windows 11, other HomePod models or firmware, stereo pairs and Apple TV groups remain unvalidated and are not newly enabled.

**Actual overnight idle and subsequent playback remain untested.** Sleep/wake, physical network-outage recovery, other Home access/PIN policies and a complete fresh-driver installation still need hardware checks. The executable is unsigned and has no automatic-update channel. See the [compatibility record](https://github.com/shenmuegit/AppleHomePod-windows/blob/main/docs/COMPATIBILITY.md).
