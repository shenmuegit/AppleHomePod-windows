# AppleHome 0.2.0 Preview 2

A smaller setup interface and a startup fix, validated with normal music on **Windows 10 Pro 22H2 (build 19045, x64) and one HomePod mini running software 27.0**.

## What changed

- Centered HomePod artwork and device identity, a clear hearing question, and refined replay and confirmation buttons.
- Visible keyboard focus, compact-window layout, and Windows system-color fallback.
- Startup preroll now begins after HomePod discovery metadata is qualified. Discovery no longer consumes the capture queue's two-second capacity before a transport can start. Stopping a route also clears its discovery wait timestamp.

The startup repair preserves the existing queue limit and per-device timing record. Everyday playback still uses Windows output, volume and mute controls.

## Install or update

Download **`AppleHome-0.2.0-ec4a0e797fed.zip`**, extract it, and open `AppleHome.exe`. The app is self-contained. The wizard handles driver setup, device discovery, output naming and timing parameters; its current language is Simplified Chinese. Use `再播放一次` to replay, `听到了` to confirm, or `没听到` to retry.

For an existing preview, use the maintenance commands in the attached **`INSTALL.md`** or the [English installation guide](https://github.com/shenmuegit/AppleHomePod-windows/blob/main/docs/installation.md#update-an-existing-preview). Reopening the wizard alone does not upgrade an installed binary.

## Validation

The exact attached executable was installed over an existing qualified setup. Normal music remained continuous; Windows volume changes and recovery after at least 15 seconds of mute were confirmed by the listener. Endpoint readbacks, an owned ready background task, and the preserved binding/calibration were checked. The mute interval was not independently timed.

- **806 .NET regression tests** passed after the startup repair, including checks that discovery does not begin preroll early and that output reselection gets a fresh wait interval.
- **22 published-app UI checks** passed with a simulated device and no audio. The UI screenshot in the README uses this mock confirmation state.
- The unchanged Python code retains its earlier **125-test and Ruff** results. There is no configured GitHub Actions workflow; these are local validation results.
- The final observed music session had about 452 seconds of uptime with zero send or synchronization errors. Internal capture-to-send p95 was about 33 ms; this is **not** measured acoustic latency or a video-sync guarantee.

No generated audio, short tones or network-disconnection tests were used for this acceptance.

## Compatibility and limits

The current native wizard enables the single HomePod mini `AudioAccessory5,1 / 27.0` profile. Windows 11, other Windows builds, other HomePod models or firmware, stereo pairs and Apple TV groups remain unvalidated and are not newly enabled by this release.

A complete fresh-driver installation and restart, a 30-minute or overnight run of this binary, sustained video synchronization, and network-outage recovery remain untested. Earlier builds completed 30-minute music and approximately five-minute subjective video checks on the same device; those results do not qualify this binary. The executable is unsigned and has no automatic-update channel. See the [compatibility matrix](https://github.com/shenmuegit/AppleHomePod-windows/blob/main/docs/COMPATIBILITY.md).
